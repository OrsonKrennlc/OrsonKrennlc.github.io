# Junyang Shen Portfolio 架构审查报告

> 首次审查日期：2026-08-05<br>
> 最近同步日期：2026-08-07<br>
> 范围：首页、建筑页、小工具集、项目数据管线、交互状态、静态资源和设计规范治理清单。

## 1. 结论

当前站点由首页、建筑页和小工具集三个页面组成，内容以静态作品展示为主。继续保留原生 HTML、CSS 和 JavaScript，是比引入前端框架更轻、更稳定的方案；框架迁移会增加构建、依赖和部署成本，却不会为当前内容规模带来相应收益。

优化采用“强化静态架构”的方向：保持现有 GitHub Pages 交付方式，先修复数据双写、动态模板注入、交互语义、弹窗状态与失败降级，再按确认范围完成首轮 UI 一致性治理。

## 2. 已完成的架构治理

### 页面与语义

- 首页、建筑页和小工具集现在各自只有一个 `h1`，装饰性叠字不再污染标题层级。
- 建筑项目卡改为原生按钮，不再依赖可点击 `div`。
- 画廊圆点、关闭和前后翻页均为带名称的原生按钮。
- 无效的 `href="#"` 已从未完成的摄影和旅行卡片移除。
- 主导航增加可访问名称和当前页面标记。
- 静态图片增加固有尺寸、替代文本、异步解码和按需加载。
- 首页内联背景图样式已迁移至 CSS 修饰类。

### 项目弹窗与画廊

- 补齐 `dialog` 语义、标题和描述关联。
- 支持 `Esc`、遮罩点击和关闭按钮三种关闭路径。
- 打开时锁定背景、限制焦点于弹窗；关闭后恢复原页面焦点。
- 支持键盘左右方向键切换图片。
- 动态图片提供项目名、图片序号和总数。
- 动态节点全部通过 DOM API 与 `textContent` 创建，不再将项目数据拼接为 `innerHTML`。

### 数据架构

- 各项目目录中的 `context.csv` 管理中文内容，`translations.en.json` 集中管理英文翻译。
- `assets/arch/projectsData.js` 明确为生成产物，并带有禁止手工编辑的文件头。
- 删除已经与实际项目失同步的 `projects.json`。
- 重写数据构建脚本，补齐编码兼容、图片类型过滤、坐标校验、字段校验和 `--check` 同步检查。
- 修复项目 003 源数据中的误输入符号，并将已有但未进入页面的设计人员和完整项目描述同步到生成数据。

### 稳定性与性能

- Hero 图片预加载；其余内容图片延迟加载。
- Leaflet、项目数据和页面逻辑改为延迟执行，减少首屏阻塞。
- 地图资源失败时，项目列表继续工作，并显示独立降级信息。
- 增加中英文系统字体回退。
- 增加 `prefers-reduced-motion` 支持。
- 新增无第三方依赖的站点校验脚本，覆盖 HTML 结构、本地资源、CSS 图片引用和项目数据完整性。

### 国际化体系

- 新增集中式 `SiteI18n` 运行时，统一管理中文和英文状态。
- 首次访问跟随浏览器语言，用户选择保存在本地并跨页面延续。
- 顶栏新增 `中 / EN` 切换控件，页面一次只显示一种语言。
- 页面标题、描述、导航、正文、图片替代文本和 ARIA 名称同步翻译。
- 四个建筑项目的标题、说明、地点、类型、作者和完整描述均提供中英文版本。
- 项目列表、地图提示、弹窗与画廊在语言切换后即时更新，无需重新加载页面。
- 站点校验新增中英文翻译键对齐、引用完整性和项目本地化检查。

### 已确认的 UI 与内容治理

- 建筑页向下箭头改为深色，并恢复原始宽高比。
- 按用户指定，首页引语调整为中文“少即是多。”、英文“Less is more.”，肖像与作者标注保持不变。
- 未激活导航由 `#B7B7B7` 提升为 `#676767`。
- 全站增加品牌化 `:focus-visible`，暗底区域使用白色反相焦点。
- 首页移动端页边距统一为 `20px`。
- 简历区最大宽度由 `1620px` 收敛为 `1200px`。
- 统一日期连接号、面积千位分隔与单位、项目类型格式和页脚文案，并在后续 i18n 治理中取消中英文并排。

## 3. 保留不变的架构决策

- 不引入 React、Vue、Vite 或包管理器。
- 不把公共导航和页脚改成运行时 JavaScript 注入，避免无脚本时丢失核心导航。
- 不把项目数据改为运行时 `fetch`，因此页面在 GitHub Pages 和本地直接打开时都能读取项目资料。
- 不改变 GitHub Pages 部署结构，不引入新的托管配置。
- 除已确认的 UI 治理项外，不改变字号、主要配色、图像裁切与常规交互动效。

## 5. 验收结果

- 三个页面均满足唯一主标题、无重复 ID、图片替代文本和显式按钮类型要求。
- HTML、CSS、JavaScript 和全部本地资源引用有效。
- 四个建筑项目的数据与各自 CSV 源文件一致，全部项目图片存在。
- 数据生成结果可重复，并通过同步检查。
- 四个 JavaScript 文件和两个 Python 脚本通过语法检查。
- 首页、建筑页、小工具集、样式、脚本和项目数据均可通过本地 HTTP 正常访问。

## 6. 后续维护流程

1. 修改某个项目目录的中文 `context.csv`、图片或 `translations.en.json` 英文翻译。
2. 运行项目数据构建脚本，更新 `projectsData.js`。
3. 新增界面文字时，在 `js/i18n.js` 同时补齐 `zh` 与 `en` 键。
4. 运行数据同步检查和站点校验。
5. 预览正常后再发布到 GitHub Pages。

任何视觉规则变更应先更新 `DESIGN_GUIDELINES.md` 的决策记录，再按影响范围扩散至三个页面，避免局部修补造成新的不一致。
