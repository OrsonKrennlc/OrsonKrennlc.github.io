# Jerry Shen Portfolio 设计规范

> 版本：1.0<br>
> 基线日期：2026-08-05<br>
> 适用范围：首页、建筑项目页，以及后续新增的摄影、旅行、个人介绍和项目详情页面。

## 1. 文档目的

本规范从当前网站的实际实现中提炼设计语言，用于保持后续页面在视觉、交互和内容表达上的一致性。

文档中的规则分为两类：

- **现状基线**：当前页面已经稳定呈现的特征，新增设计应优先继承。
- **统一建议**：当前实现中尚未完全统一，但后续应逐步采用的规范。

这是一套面向个人作品集的设计系统，不追求企业产品式的高密度和强功能感。所有扩展都应首先服务于作品、空间与个人叙事。

## 2. 当前页面设计总结

### 2.1 页面结构

| 页面 | 当前结构 | 主要任务 |
| --- | --- | --- |
| 首页 `index.html` | 固定导航 → 山景主视觉 → 个人介绍 → 黑底引语 → 教育与奖项 → 三类项目入口 → 页脚 | 建立个人气质并提供作品入口 |
| 建筑页 `architect.html` | 固定导航 → 项目地图 → 项目列表 → 项目详情弹窗 → 页脚 | 按地理位置浏览项目，并阅读完整建筑资料 |
| 小工具集 `tools.html` | 固定导航 → 页面引言 → 应用目录 → 持续更新提示 → 页脚 | 集中展示可直接使用的网页应用及其开源仓库 |

首页采用从山景灰白到纯黑、再转入纯白的长篇叙事。建筑页则使用近乎纯白的展览式画布，让地图、模型图和项目数据成为主体。

### 2.2 核心视觉气质

网站可以概括为以下六个关键词：

1. **安静**：低饱和影像、黑白灰底色、克制的动效。
2. **编辑感**：大标题、长留白、清晰的章节转换，接近摄影集或建筑作品册。
3. **空间感**：内容不追求填满屏幕，通过 1200px 内容宽度和大段垂直间距形成呼吸。
4. **多语可切换**：中文与英文各自形成完整阅读体验；藏文作为地域文化原文保留，并随界面语言切换对应译文。
5. **影像主导**：风景、建筑与人物影像负责情绪，界面装饰保持低存在感。
6. **深绿识别**：`#02542D` 是品牌强调色，用于标志、导航状态、项目副标题、地图点和关键控件。

### 2.3 设计原则

后续设计应遵循以下原则：

- **让作品先说话**：界面为图像和项目文字提供秩序，不增加无叙事价值的装饰。
- **留白也是内容**：大面积空白与暗部是节奏的一部分，不应为了“信息量”随意压缩。
- **一种强调色就够了**：深绿承担品牌识别；页面中的其他颜色主要来自作品影像。
- **中英文字体各司其职**：中文用宋体建立人文与出版气质，英文和数据用等宽字体建立理性秩序。
- **动效服务方向感**：动效只表达进入、展开、聚焦和层级变化，不做持续抢眼的表演。
- **移动端重新编排，而非机械缩小**：列布局转为纵向，弹窗转为近全屏，信息保持可读与可触达。

## 3. 设计基础

### 3.1 色彩

#### 现状基线

| 语义 | 色值 | 当前用途 |
| --- | --- | --- |
| 品牌深绿 | `#02542D` | Logo、激活导航、地图标记、项目副标题、弹窗标题与控件 |
| 纯黑 | `#000000` | 暗色章节、主文字、叠字中心层 |
| 纯白 | `#FFFFFF` | 页面画布、卡片、反白文字 |
| 主边框 | `#EAEAEA` | 导航和页脚分隔、地图与悬停卡片边框 |
| 暗底次级文字 | `#D0D0D0` / `#CBCBCB` | 个人介绍、引语署名、叠字层 |
| 亮底次级文字 | `#676767` / `#808080` | 简历说明、项目标签、辅助控件 |
| 未激活导航 | `#676767` | 白底导航的默认状态 |

#### 统一建议

新增样式不得直接散写灰色值，应先使用语义变量：

```css
:root {
  --color-canvas: #FFFFFF;
  --color-inverse: #000000;
  --color-brand: #02542D;

  --color-text: #000000;
  --color-text-muted: #676767;
  --color-text-subtle: #808080;
  --color-text-on-dark: #FFFFFF;
  --color-text-on-dark-muted: #D0D0D0;

  --color-border: #EAEAEA;
  --color-overlay: rgba(0, 0, 0, 0.60);
  --color-image-overlay: rgba(0, 0, 0, 0.30);
  --color-image-overlay-hover: rgba(0, 0, 0, 0.50);
}
```

使用约束：

- 品牌深绿只用于身份、激活状态和关键交互，不用于大面积背景。
- 可点击文字不得使用弱于 `#676767` 的灰色；更浅的灰色只用于非关键装饰。
- 作品图片保持原色，不统一套品牌色滤镜。
- 暗色区域中的正文优先使用 `#D0D0D0`，标题使用白色，避免整段纯白造成眩光。

### 3.2 字体

#### 字体家族

| 角色 | 字体 | 用途 |
| --- | --- | --- |
| 中文主字体 | `Noto Serif SC` | 中文标题、正文、导航、项目数据 |
| 英文与数据字体 | `Anonymous Pro` | 英文标题、英文正文、日期、数字、按钮 |
| 品牌签名字体 | `Caveat` | 仅用于 `Junyang Shen` Logo |
| 藏文字体 | `Noto Serif Tibetan` | 仅用于藏文内容 |

字体回退建议：

```css
--font-zh: "Noto Serif SC", "Songti SC", "STSong", serif;
--font-en: "Anonymous Pro", "Courier New", monospace;
--font-tibetan: "Noto Serif Tibetan", serif;
--font-signature: "Caveat", cursive;
```

#### 字号层级

| 层级 | 桌面端 | 移动端 | 字重 | 行高 | 典型用途 |
| --- | ---: | ---: | ---: | ---: | --- |
| Hero Display | 48px | 20px | 400 | 1.0–1.15 | 首页拉丁文叠字 |
| Section Display | 48px | 32px | 400/700 | 1.2 | 项目存档大标题 |
| Page / Modal Title | 36px | 24px | 600–700 | 1.25 | 地图标题、弹窗标题 |
| Content Heading | 32–36px | 24–28px | 400–700 | 1.3 | 简历、项目卡标题 |
| Lead Body | 20px | 16px | 300–400 | 1.6 | 介绍、教育信息、较短说明 |
| Body | 16px | 14–16px | 400 | 1.6–2.0 | 项目元数据与长描述 |
| Meta | 14–16px | 14px | 400 | 1.5 | 地点、标签、页脚 |

排版规则：

- 中文内容必须显式使用中文字体；英文、年份、面积等数据优先使用英文等宽字体。
- 长篇项目描述建议每行不超过约 38 个中文字符，正文行高使用 `1.8` 至 `2`。
- 大标题允许较紧行高；正文不得使用小于 `1.5` 的行高。
- Logo 字体不可用于正文或栏目标题。
- 英文按钮使用大写时保持 `0.08em–0.1em` 字距，例如 `MORE +`。

### 3.3 间距与网格

#### 统一建议

采用 4px 基础单位，优先从以下刻度取值：

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 60 / 80 / 100 / 120 / 150`

页面级规则：

```css
:root {
  --page-gutter: clamp(20px, 7.8vw, 150px);
  --content-max: 1200px;
  --text-max: 720px;
  --header-height: 100px;
}
```

- 桌面端内容最大宽度统一为 `1200px`，居中显示。
- 首页简历当前允许扩展至 `1620px`，后续应评估后收敛到同一容器或明确设为“宽内容容器”。
- 桌面端页面左右安全边距上限为 `150px`，中等屏幕为 `50px`，移动端统一为 `20px`。
- 普通区块上下间距使用 `80–150px`；卡片间距使用 `40px`；组件内部主要间距使用 `20–40px`。
- 视觉叙事区可以突破常规间距，例如首页山景段，但必须有明确的画面构图理由。

### 3.4 圆角、边框与阴影

| Token | 建议值 | 用途 |
| --- | ---: | --- |
| 小圆角 | 4px | 项目图片、画廊图片 |
| 大圆角 | 16px | 地图容器、桌面弹窗 |
| 细边框 | 1px `#EAEAEA` | 导航、页脚、地图、卡片悬停 |
| 卡片悬停阴影 | `0 15px 40px rgba(0,0,0,.10)` | 建筑项目卡 |
| 弹窗阴影 | `0 20px 50px rgba(0,0,0,.20)` | 项目详情弹窗 |

保持克制：常态卡片无阴影，只有在交互或层级确实抬升时才出现阴影。

### 3.5 影像规范

- 影像方向：自然、建筑、旅行、真实环境；偏低饱和，重视空气感、材料和光线。
- 首页 Hero 使用纵向山景，并通过底部黑色渐变自然过渡到暗色介绍区。
- 首页分类卡采用 `1:1`，图片 `cover`，文字居中叠加。
- 建筑项目列表缩略图当前为 `400 × 250`，即约 `8:5`；同一列表应保持固定比例。
- 项目详情图使用 `contain`，优先展示完整图纸或建筑画面，不为填满容器而裁掉信息。
- 所有内容图片必须提供有意义的 `alt`；纯装饰图应使用空 `alt=""`。
- 不在图片上叠加复杂渐变或多种颜色。需要提高文字可读性时，只使用黑色半透明遮罩。

## 4. 布局与响应式

### 4.1 断点

沿用现有两级断点：

| 范围 | 定义 | 布局策略 |
| --- | --- | --- |
| `≥ 1200px` | 桌面 | 150px 最大页边距，多列布局，固定导航 |
| `769–1199px` | 中屏 | 50px 页边距，内容适度收拢，分类卡转为单列 |
| `≤ 768px` | 移动 | 20px 页边距，全部主内容单列，弹窗近全屏 |

不要新增只为修补单个元素的随机断点。确需新增时，必须证明是内容发生断裂，而不是为了适配某一设备型号。

### 4.2 容器类型

- **标准容器**：最大宽度 `1200px`，用于地图、建筑项目卡、个人介绍和大多数内容区。
- **文本容器**：最大宽度约 `720px`，用于长描述、文章和项目叙事。
- **全宽叙事区**：用于 Hero、黑底引语、全宽背景与章节转场。

### 4.3 移动端原则

- 移动端导航进入单列菜单面板，每个交互项的最小触控区域应达到 `44 × 44px`。
- 桌面双列内容按“标题 → 图像 → 元数据 → 正文 → 操作”的阅读顺序转为单列。
- 项目卡的绝对定位按钮在移动端恢复文档流，避免遮挡内容。
- 详情弹窗在移动端使用近全屏布局，圆角可减小；正文和图片保持自然滚动。
- 不通过隐藏核心项目数据来换取简洁，优先改变排版。

## 5. 组件规范

### 5.1 顶部导航

**现状基线**

- 桌面高度 `100px`，白色 `95%` 透明背景，`4px` 背景模糊和底部细边框。
- Logo 位于左侧，主导航位于右侧，导航间距 `40px`。
- 激活与悬停状态使用品牌深绿，非激活状态为灰色。

**统一建议**

- 每个页面必须准确标记当前栏目，不用滚动点击状态代替路由状态。
- 增加清晰的键盘焦点样式，例如 `2px` 品牌色外框和 `2px` 偏移。
- 移动端顶栏采用 `72px` 高的粘性紧凑横排，仅显示品牌签名与菜单按钮；导航和语言切换进入下拉面板，面板打开时仍保留完整键盘路径并支持 `Esc` 关闭。
- 顶栏一次只显示当前语言，不再并排中英文；语言切换控件固定为紧凑的 `中 / EN`。

### 5.2 首页 Hero

**组成**：山景背景、五层错位拉丁文、地点、藏文与中文、向下箭头。

- 五层标题以 `30px` 的桌面错位和 `15px` 的移动端错位形成“地层/回声”效果。
- 移动端使用原始纵向山景的完整宽度构图，拉丁文控制在 `21–30px`，地点、藏文和箭头沿画面纵向依次展开，不用额外空容器撑高首屏。
- 藏文名言在移动端使用无明确边界的径向羽化暗部与柔和文字阴影，白色藏文配浅灰译文；禁止使用封闭黑色卡片遮挡山景。
- 中心层为黑色，外层由深到浅，避免使用彩色故障效果。
- Hero 只允许一个核心句，不叠加按钮组、标签云或社交图标。
- 向下箭头必须可点击、可聚焦，并指向下一段有效内容。
- 尊重 `prefers-reduced-motion`，关闭平滑滚动和非必要动画。

### 5.3 个人介绍区

- 桌面使用 `200px` 方形图像与文本横排，间距 `60px`。
- 移动端改为 `88–112px` 图像与文字的紧凑双列，整体左对齐并以顶部细线建立章节起点；极窄文本允许自然换行。
- 信息顺序固定为：姓名 → 别名 → 中文身份 → 英文身份 → 核心陈述。
- 暗底上标题用白色，其他信息用 `#D0D0D0`，避免多种近似灰色无规则混用。

### 5.4 引语区

- 作为暗色叙事的收束，保持居中和高留白。
- 头像使用 `60px` 圆形；主引语约 `32px`；署名约 `20px`。
- 移动端取消负边距叠压，以 `72–96px` 的独立上下留白收束暗色叙事。
- 每个页面最多使用一个引语区，且引用应与个人设计观或该栏目主题直接相关。
- 引语文字、作者和年份应是可选择文本，不写入图片。

### 5.5 章节标题

章节标题一次只显示当前语言，并使用同一个翻译键驱动。

```html
<h2 class="section-title"><strong data-i18n="archives.title">项目存档</strong></h2>
```

- 中英文共享同一层级、容器和间距，不因语言切换改变组件身份。
- 同一级标题在不同页面使用同一字号；英文过长时允许自然换行，不单独缩小字号。
- 标题中不再使用 `｜` 或 `/` 拼接两种语言。

### 5.6 首页分类卡

- 采用方形、整图背景、居中文本和 `30%` 黑色遮罩。
- 移动端仍保持方形，但卡片间距收敛为 `20px`，标题左侧章节标题保持编辑式左对齐。
- 悬停时图片最多放大至 `1.05`，遮罩加深到 `50%`，时长分别为 `500ms` 和 `300ms`。
- 卡片必须整体可点击；不可用 `href="#"` 作为未完成入口。未完成栏目应标记“建设中”或暂不作为链接。
- 键盘焦点状态应获得与悬停等价的视觉反馈。

### 5.7 建筑项目卡

**桌面结构**：项目编号 + 固定比例缩略图 + 项目信息 + `MORE +`，奇偶项目交替图文方向形成编辑式浏览节奏。

- 卡片最大宽度 `1200px`，桌面内边距为 `40px 24px`，图文间距 `40–56px`；缩略图保持 `8:5`。
- 默认仅以顶部细分隔线组织项目，不形成封闭盒子；悬停或聚焦时通过轻微位移、阴影和图片缩放抬升。
- 元数据使用两列网格，标签灰色、值黑色，行间距 `12px`。
- 整卡可点击时，应使用语义化链接或按钮，不能只给 `div` 绑定点击事件。
- 项目数据字段顺序固定为：时间、地点、类型、面积、容积率、绿地率、设计人员。
- 缺失字段不显示空行，但同类卡片的剩余字段顺序不得改变。

### 5.8 地图

- 建筑页首屏在桌面端采用左侧项目概览、右侧地图的等宽双栏结构；左侧包含栏目标题、简短说明和可展开的项目快捷索引。
- 桌面端首屏只保留两栏内部的顶部留白，不在固定顶栏下重复增加外部留白；两栏顶部不使用分割线。
- 采用浅色底图，避免与作品图片争夺视觉注意。
- 标记为 `14px` 深绿圆点、`2px` 白色描边。
- 指针悬停或键盘聚焦标记时，以轻量浮层同时显示项目封面和名称；点击标记平滑滚动至对应项目卡。
- 地图桌面高度约 `480px`，移动端 `300px`，容器圆角 `16px`。
- `900px` 以下概览与地图改为单列，顺序固定为标题与快捷索引 → 地图。
- 默认关闭滚轮缩放，避免干扰页面纵向浏览。
- 快捷索引必须使用语义化按钮、暴露展开状态，并支持平滑跳转与减少动态效果偏好；项目浏览不能只依赖地图。

### 5.9 项目详情弹窗与画廊

- 桌面宽度为视口 `90%`、最大 `1200px`、最大高度 `90vh`。
- 遮罩为 `60%` 黑色并使用轻微模糊，明确页面层级。
- 标题使用品牌深绿；主图在浅灰展板中完整显示，高度随视口在 `360–620px` 之间响应；下方为元数据与项目描述双列。
- 画廊同时显示 `当前序号 / 总数`、进度圆点和前后翻页按钮；圆点的视觉尺寸克制，但触控区域不得小于 `28px`。
- 弹窗打开时锁定背景滚动，关闭后恢复。
- 必须支持：关闭按钮、遮罩点击关闭、`Esc` 关闭、焦点圈定、关闭后焦点返回触发卡片。
- 关闭按钮和前后翻页按钮必须提供可访问名称；画廊图片必须有项目相关 `alt`。
- 圆点只表示进度，不应成为唯一的翻页方式；移动端可增加滑动手势，但仍保留按钮。

### 5.10 页脚

- 桌面为三段横排，移动端纵向居中。
- 使用 `14–16px` 英文等宽字体和顶部细边框。
- 版权文本格式统一为 `© 2026 Orson Krennic. All rights reserved.`，品牌名与句号之间保留空格。
- 情感化文案可以保留，但每段应简短，不压过作品内容。

## 6. 交互与动效

### 6.1 时长

| Token | 时长 | 用途 |
| --- | ---: | --- |
| Fast | 150ms | 焦点、轻微颜色变化 |
| Standard | 300ms | 导航、遮罩、弹窗淡入淡出 |
| Slow | 500ms | 图片轻微缩放 |

推荐缓动：

```css
--ease-standard: cubic-bezier(.2, .8, .2, 1);
```

### 6.2 使用规则

- 默认只动画 `opacity`、`transform` 和颜色，避免动画布局尺寸。
- 所有悬停状态必须有键盘聚焦等价状态。
- 不使用循环漂浮、持续闪烁、视差滚动或高强度 glitch 动画。
- 平滑滚动只用于用户明确触发的页内导航。
- 在 `prefers-reduced-motion: reduce` 下，将非必要动画时长设为接近 `0ms`，并改用即时滚动。

## 7. 内容规范

### 7.1 国际化与语言切换

- 支持 `zh` 与 `en` 两个完整语言包；页面一次只显示一种界面语言。
- 首次访问跟随浏览器语言，之后使用本地存储记住用户选择。
- 跨页面链接必须携带 `?lang=zh` 或 `?lang=en`，以兼容 `file://` 预览时不同 HTML 文件之间可能存在的存储隔离；URL 参数优先于本地存储。
- 顶栏使用 `中 / EN` 切换，按钮通过 `aria-pressed` 表达当前语言。
- `<html lang>`、页面标题、描述、可见文本、替代文本和 ARIA 名称必须同步切换。
- 静态文本使用 `data-i18n` 与属性翻译标记；动态文本通过 `SiteI18n.t()` 获取。
- 建筑项目中文内容来自 `context.csv`，英文内容来自 `translations.en.json`，生成产物将两种语言按项目封装。
- 专有名词、拉丁文原句、藏文原文、日期和数字可以保持原文；其解释性文字必须翻译。
- 新增翻译键必须同时提供中文和英文，不允许仅在界面上拼接临时译文。

### 7.2 项目数据

- 日期统一为 `YYYY.MM–YYYY.MM`，范围使用连接号 `–`。
- 教育经历与荣誉奖项按时间倒序排列；跨日期区间以结束时间为主、开始时间为辅，越近的内容越靠前。
- 面积统一为 `9,300 m²`，使用千位分隔和平方符号。
- 比率统一为纯数字或百分比，避免同一字段出现多种格式。
- 项目描述按“背景 / 策略 / 空间 / 材料 / 影响”组织，短项目不必强行凑齐段落。
- 项目内容按语言分源管理：`context.csv` 是中文源文件，`translations.en.json` 是英文翻译源；`projectsData.js` 由构建脚本生成，不得手工编辑。

### 7.3 语气

- 保持第一人称作品集语气：准确、克制、有个人判断。
- 少用空泛的宣传词，优先描述场地、问题、方法和结果。
- 英文翻译以自然表达为先，不逐字复制中文句式。

## 8. 可访问性与可用性底线

以下项目是新增页面的验收条件，也是现有页面的优先补齐项：

- 正文与背景达到 WCAG AA 对比度；浅灰只用于非关键辅助信息。
- 所有交互可通过键盘完成，并有清晰的 `:focus-visible` 状态。
- 触控目标至少 `44 × 44px`。
- 页面使用正确的标题层级，一个页面只有一个主标题。
- 卡片、关闭、翻页等交互使用原生链接或按钮。
- 图片提供准确的替代文本；装饰图片不重复朗读。
- 弹窗具备 `role="dialog"`、`aria-modal="true"`、可访问标题和焦点管理。
- 地图、画廊和动效都有不依赖视觉或运动的替代方式。
- 字体加载失败时仍保持合理的中文、英文与藏文回退。

## 9. 工程实现约定

### 9.1 样式组织

- 全局 token、重置、导航、页脚和通用组件放在 `css/style.css`。
- 页面特有布局放在独立文件，例如 `css/architect.css`。
- 新增页面优先复用通用类，不复制导航和页脚样式。
- 全站静态翻译由 `js/i18n.js` 集中管理；页面不得自行维护第二套语言状态。
- 颜色、间距、圆角、容器宽度和动效时长使用 CSS 变量。
- 禁止在 HTML 中新增内联样式；项目背景图通过组件修饰类引用。

### 9.2 组件状态

每个交互组件至少定义：

`default / hover / focus-visible / active / disabled`

数据型组件还应定义：

`loading / empty / error`

例如地图加载失败时，应保留项目列表并显示简短提示；画廊无图片时，不显示空白翻页控件。

### 9.3 外部依赖

- 当前字体依赖 Google Fonts，地图依赖 Leaflet、OpenStreetMap 与 CARTO。
- 外部资源失败不能阻断主体内容；项目列表和正文必须继续可读。
- 发布前验证 GitHub Pages 下的相对路径、跨域资源和 HTTPS 加载。
